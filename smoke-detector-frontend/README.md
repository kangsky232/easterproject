# 智慧烟感预警系统前端

更新日期：2026-09-01。

该目录是与 `backend/` 配套的 Vue 3 管理界面，使用 Vite、TypeScript、Pinia 和 ECharts。它负责展示、交互和调用后端 API；MySQL、告警规则、权限校验及外部通道状态以后端为准。

## 运行要求与命令

- Node.js 18+ 和 npm。
- Spring Boot 后端默认运行在 `http://127.0.0.1:8080`。
- MySQL 初始化、后端账号和可选 MQTT/RAG 配置见仓库根目录 README 与 `../docs/DEVELOPMENT.md`。

在本目录运行：

```powershell
npm install
npm run dev
```

也可在 Windows 双击 `start.bat`；它仅在没有 `node_modules` 时执行 `npm install`，随后运行 Vite，不会启动 MySQL 或后端。Vite 首选 `http://127.0.0.1:5173`，端口被占用时会选择下一个可用端口。

可用 npm 脚本：

| 命令 | 实际行为 |
| --- | --- |
| `npm run dev` | 启动 Vite 开发服务器。 |
| `npm run type-check` | 仅运行 `vue-tsc --noEmit`。 |
| `npm run build` | 先做 TypeScript 检查，再构建到 `dist/`。 |
| `npm run preview` | 本地预览已有的 `dist/` 构建结果。 |

开发模式下浏览器请求相对路径 `/api`，由 Vite 代理到 `http://127.0.0.1:8080`。`VITE_API_BASE` 未设置时默认为空字符串；部署到独立静态站点时必须在构建阶段设置为实际 HTTPS 后端地址，且不要带末尾 `/`。

## 页面与交互现状

### 新版首页

应用默认进入 `HomeView`。首页包含背景主视觉、浅色/深色主题开关、登录/退出入口、按后端工作区权限过滤的模块导航，以及“进入监控大屏”入口。它不是独立路由，刷新页面会重新从首页开始。

首页中的产品介绍属于展示文案，不代表已经取得工业级认证、实现趋势预测、具备 7×24 小时高可用，或已接入所有“多端推送”通道；实际能力边界见下文。

### 监控大屏与趋势

监控大屏包含 KPI、设备列表、传感器趋势和告警列表。选择设备后可切换以下指标：烟雾浓度、环境温度、湿度、设备电流、线缆温度和 CO；蜂鸣器状态只显示当前值。

- “实时”读取该设备最近 120 条原始记录，并随全局轮询约每 3 秒刷新。
- “24小时”“7天”“30天”分别请求后端聚合趋势，当前使用 15 分钟、60 分钟和 240 分钟聚合桶。
- 图表支持悬浮提示、滚轮/滑块缩放；烟雾浓度图显示设备阈值线，其他指标不使用烟雾阈值线。
- 后端断开时轮询会指数退避，最长 60 秒；当前没有 WebSocket/SSE 实时推送。

代码中保留了 `TrendView.vue` 和 `MiniTrendChart.vue`，但当前首页、导航和监控大屏都没有触发 `navigate('trend')` 的入口。因此独立“趋势详情页”目前不可达，不能作为已开放页面验收；现阶段应在监控大屏内使用 `TrendChart`。

### 全局右下角智能助手

登录成功且当前角色拥有 `chat` 模块时，各应用视图右下角都会显示助手入口。打开后是固定在右下角的白底非模态小窗，桌面端最大约 `440 × 620` 像素；窄屏下扩展到接近可视区域，但不会替换当前业务页面。

助手支持快捷问题、文本输入、结构化风险建议和关闭键 `Esc`。语音输入依赖浏览器 Web Speech API，代码仅按 Chrome/Edge 支持处理。提问时会附带当前所选设备的活动告警 ID（若存在）；RAG 服务或模型不可用时，后端/知识服务会降级到内置安全规则。回答仅用于辅助研判，紧急情况仍需现场核验、疏散并拨打 119。

聊天消息只保存在当前组件内存中：关闭后再次打开仍保留本次页面会话，刷新页面或关闭标签页后丢失，不会写入 `localStorage`，也没有服务端会话历史。

### 3D 地图与设备楼层定位

社区三维态势从 `GET /api/map/scene` 获取楼栋和设备位置。地图可旋转、缩放，并支持点击楼栋立面或楼层按钮联动查看：

- 当前楼层的设备、在线/离线/告警状态、最新遥测和房间标签。
- 设备标记按数据库中的 `buildingCode`、`floorNo`、楼内 `positionX`/`positionZ` 投影到当前视角最近的楼栋立面，减少标记落到相邻楼层的视觉偏差；当前数据库中的 501 设备应显示在 5 层。
- 点击设备标记会同步选择其楼栋和楼层；小区管理员或系统管理员在拥有 `MAP_POSITION_MANAGE` 权限时可修改楼栋、楼层、房间及楼内坐标。
- 后端校验楼层不能超过楼栋层数，X/Z 不能超过楼栋尺寸；未配置位置的已绑定设备可能由后端首次读取场景时分配模拟位置。

楼层监控使用 21 张静态演示图，其中 19 张对应各楼层常规画面、2 张用于预警展示；点击画面可打开大图预览，通过关闭按钮、遮罩空白处或 `Esc` 退出。它们不是摄像头视频，也不是 `ai-vision` 服务的实时推理结果。地图刷新失败时，旧的在线标记会按离线展示并提示数据过期。

社区三维态势页下方还包含 AI 视觉实时巡检面板：后端启动后默认暂停，消防员、小区管理员和系统管理员点击一次开始后立即识别第一帧，随后持续自动运行，直到点击暂停；运行时 15 个模拟机位（10 张正常、5 张疑似烟火）按洗牌顺序随机轮换，每轮全部出现一次且相邻不重复，暂停后不再自动分析或发送新的钉钉告警。前端只保留开始/暂停控制，不提供逐帧识别按钮。面板展示当前帧、模型置信度、风险等级、可见依据、钉钉投递状态、待人工判断和最近事件。后端配置 DeepSeek Key 时由 `deepseek-v4-flash-vision-exp` 分析；未配置时界面明确显示“模拟规则降级”。工作人员填写依据后可一次性确认为火情或排除误报；居民只读。

### 其他已接入界面

- JWT 登录、当前用户与后端角色工作区；后端权限校验仍是最终边界。
- 设备查询、绑定、编辑、阈值、位置和解绑；设备访问令牌只在创建/轮换响应后一次性展示。
- 告警查询、确认、解决、误报标记及规则辅助复核。
- 隐患管理支持优先级/状态筛选、居民上报、工作人员接单整改、提交结果、管理员复核关闭或驳回重做，并显示全过程时间线和首页未闭环统计。
- 通知记录、广播记录与用户管理；具体入口随角色权限变化。
- 所有数值遥测统一显示两位小数；旧版本已截断的历史小数无法恢复。

## `localStorage` 与多标签页限制

前端会持久化三个同源键：

| 键 | 内容 |
| --- | --- |
| `smart-smoke.token` | JWT。 |
| `smart-smoke.user` | 当前用户的前端缓存。 |
| `smart-smoke.theme` | `light` 或 `dark`。 |

`localStorage` 以浏览器同源（协议、主机、端口）隔离。相同来源的多个标签页或窗口共享这些键；例如两个 `https://easterproject.pages.dev` 标签页共享登录状态，而 `localhost:5173`、`127.0.0.1:5173`、不同端口和 Pages 域名彼此不共享。

当前代码没有监听浏览器 `storage` 事件。一个标签页登录、退出或切换主题后，其他已经打开的同源标签页不会立即同步 Pinia 状态和界面，通常需要刷新。API 封装会在每次请求时重新读取共享 JWT，因此另一个标签页可能先出现 401 或账号/界面状态短暂不一致。不要在同一浏览器配置、同一来源的多个标签页中同时登录不同账号；需要并行测试角色时使用不同浏览器配置文件、隐私窗口或不同来源。

JWT 保存在持久化存储中，登出会删除它，但这不能替代 XSS 防护、HTTPS 和较短的令牌有效期。

## 能力边界

- 华为云 MQTT 入站由后端按运行配置启用；前端不能仅凭页面存在就判断 Broker 或设备在线。
- 钉钉单聊只有在后端配置机器人且员工已绑定时才会真实投递。
- APP 通知目前是数据库/页面通知记录；SMS 保持待发送记录，尚无真实短信或移动推送供应商适配器。
- MQTT 设备广播下行尚未实现；广播状态需结合后端返回的实时能力判断。
- 视觉巡检已接入后端事件、DeepSeek 可选分析、钉钉推送和人工研判闭环，但帧来源仍是静态模拟画面；`ai-vision` Flask 目录不参与当前流程。
- 智能问答可能使用 Ollama，也可能降级到本地知识规则；任何回答都不构成消防部门的正式处置结论。

`GET /api/system/capabilities` 返回的是当前进程的瞬时能力状态，应以实时响应为准，不能把某次看到的 `CONNECTED` 写成部署保证。

2026-09-01 本机未配置 DeepSeek Key，视觉能力预期为 `SIMULATION_FALLBACK`；MQTT、钉钉、后端、隧道和知识库的在线状态仍以实时能力接口为准。

## 构建与部署

Dockerfile 使用 Node 20 构建，再由 Nginx 1.27 提供静态文件；容器内 Nginx 把 `/api/` 反向代理到 Compose 网络中的 `backend:8080`，宿主机默认通过根目录 Compose 暴露 `127.0.0.1:8088`。

Cloudflare Pages 的现有配置为：

| 项目项 | 值 |
| --- | --- |
| 根目录 | `smoke-detector-frontend` |
| 构建命令 | `npm run build` |
| 输出目录 | `dist` |
| 生产分支 | `master` |
| 生产变量 | `VITE_API_BASE=https://api.kangroom.eu.cc` |

`VITE_API_BASE` 是构建时变量，修改后必须重新部署。Pages 来源还必须出现在后端 `CORS_ALLOWED_ORIGINS` 中。完整启动、Named Tunnel 和排错步骤见 `../docs/CLOUDFLARE_PAGES.md`。
