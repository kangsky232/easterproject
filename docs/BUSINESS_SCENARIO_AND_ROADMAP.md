# 业务场景与迭代路线

更新日期：2026-09-02。

## 1. 当前业务定位

本系统当前定位为面向住宅、老旧小区和出租屋的火灾风险监测与联动处置演示平台。主要用户是物业/社区安全管理员、消防巡查人员和值班人员；设备端负责采集数据，Web 管理大屏负责集中监控和处置，钉钉负责把告警与广播送达值班人员手机。

当前版本适合功能演示、毕业设计验收和小范围试点验证，尚不等同于经过消防认证的火灾自动报警系统，也不应替代法定消防设施、人工巡检和应急报警流程。MQ-2 更适合判断“是否出现烟雾/可燃气体及变化趋势”，系统中的 ppm 是近似估算值，不是实验室级绝对浓度。

## 3. 当前业务闭环

1. 设备通过 HTTP 或华为云 IoTDA MQTT 上报遥测数据，后端完成数据入库和在线状态刷新；HTTP 调用方复用 `messageId` 时可幂等重试，MQTT 当前为每次收到的消息生成新 ID，不能可靠去重 Broker 重投。
2. 3D 地图根据数据库中的楼栋、楼层、房间和设备坐标显示空间位置，并叠加在线、离线和告警状态；设备点会投影到最近的可见楼体立面，保证楼层语义不受透视深度影响（当前 501 设备位于 5 层）；值班人员可点击楼栋/楼层联动查看本层设备和模拟过道画面。
3. 规则引擎对六类传感器指标执行预警/危险判断，设备离线由定时任务单独判断。
4. 首次进入告警范围时创建活动告警，并写入站内 APP 和 SMS 记录；配置钉钉后才会尝试真实单聊并追加成功/失败的钉钉记录。APP 是站内通知记录，SMS 尚未接入供应商。
5. 同一设备、同一指标、同一严重级别的活动告警不重复轰炸；由预警升级为危险时再次发送钉钉消息。
6. AI 视觉巡检默认暂停，有权限的工作人员点击一次开始后立即识别并持续自动轮换 15 个模拟机位图片，直到点击暂停；暂停后不再自动识别或发送新消息。有 DeepSeek Key 时调用图片模型，无 Key 时明确使用演示规则。疑似结果超过阈值后建档并向钉钉发送待核查消息，同机位未复核事件不会重复轰炸。
7. 管理员或消防员在 Web 端通过 3D 空间定位与楼层巡查入口确认、辅助复核、解决或标记误报；视觉事件必须填写依据后一次性确认为火情或排除误报，钉钉会收到复核结果。通知审计页也会汇总投递异常并保存核查责任人和时间。当前过道画面与视觉输入均为明确标注的模拟图片，不作为真实证据。
8. 消防员、小区管理员和系统管理员可创建广播并下发到全部启用且已绑定员工的钉钉单聊，也可再次下发；删除广播记录只开放给小区管理员和系统管理员，且不会撤回已经送达钉钉的消息。

除自动告警处置外，页面还提供人工发现隐患闭环：所有登录角色可填写位置、优先级和情况说明上报；居民只能看到本人记录，消防员或管理员接单后提交整改结果，社区/系统管理员执行复核。复核通过进入 `CLOSED`，驳回则回到 `PROCESSING` 继续整改；上报、接单、提交、通过和驳回均写入不可省略的流转时间线。

## 4. 当前告警口径

危险规则优先于预警规则。下表中未覆盖的中间区间只进入趋势观察，不自动生成告警。例如温度 31–45℃、CO 11–49 ppm 本身不触发告警。

| 指标 | 参考正常范围 | 预警 | 危险 |
| --- | --- | --- | --- |
| 烟雾浓度 | `< 100 ppm` | `100–300 ppm` | `> 300 ppm` |
| 环境温度 | `20–30℃` | `> 45℃`，或 5 分钟内升温 `>= 10℃` | `> 60℃` |
| 环境湿度 | `40–70%` | 5 分钟内下降 `>= 20` 个百分点 | `< 20%` |
| 电气电流 | `0.5–5A` | `> 10A`，或 5 分钟内波动 `>= 5A` | `> 15A` |
| 线缆温度 | `< 50℃` | `> 70℃` | `> 90℃` |
| 一氧化碳 | `0–10 ppm` | `50–100 ppm` | `> 100 ppm` |

当前烟雾阈值固定为 100 ppm，不允许通过设备编辑页面改成其他数值，以保持告警口径一致。后续如需按房型、设备标定结果或监管要求配置阈值，应改为“规则模板 + 审批 + 版本记录”，而不是直接开放任意输入。

## 5. 当前部署场景

| 组件 | 当前地址/方式 | 说明 |
| --- | --- | --- |
| Web 前端 | [https://easterproject.pages.dev](https://easterproject.pages.dev) | Cloudflare Pages，跟随 GitHub `master` 构建 |
| 公网 API | [https://api.kangroom.eu.cc](https://api.kangroom.eu.cc) | Cloudflare Named Tunnel 固定域名 |
| 本地 API | `http://127.0.0.1:8080` | Spring Boot 在开发者电脑运行 |
| 数据库 | 本机 MySQL `smart_smoke` | 电脑关机或 MySQL 停止后不可用 |
| 手机消息 | 钉钉 Stream + 机器人单聊 | 员工首次私聊机器人后自动绑定为接收人 |

Named Tunnel 重启后不需要修改后端域名或重新配置 Pages；但本机后端、MySQL 和 `cloudflared` 都必须持续运行。固定域名只解决地址稳定性，不提供 7×24 小时可用性。

2026-09-02 本机配置中，MQTT、钉钉与 DeepSeek Vision 已启用，能力检查结果分别为 `CONNECTED`、`DINGTALK_SINGLE_CHAT` 和 `DEEPSEEK_VISION`；知识库为 `FALLBACK_ONLY`。在线状态会变化，重启服务或外部依赖变化后应重新查询 `/api/system/capabilities`。

当前主前端把登录信息保存在同源 `localStorage` 中，同一浏览器普通窗口的多个页签会共享并覆盖账号会话。并行验收不同角色时，应使用普通窗口与无痕窗口、不同浏览器或不同浏览器配置文件；若产品后续必须在同一浏览器页签中保持独立账号，需要把会话存储改为 `sessionStorage` 或引入显式的多账号会话设计。

## 6. 后续迭代方案

### P0：稳定演示版（建议 1–2 周）

- 增加住宅、阴燃、电气过载和快速火灾四套可重复的数据模拟场景，可选择设备、倍率和持续时间。
- 在现有可点击楼层的 3D 地图上继续增加楼层剖面细节、火情扩散动画和场景模拟联动，不改变真实告警记录的审计语义。
- 为后端、MySQL 和 Named Tunnel 增加一键启动、启动前检查、进程守护及清晰日志。
- 增加告警恢复判定、迟滞区间和冷却时间，减少临界值抖动；保留当前预警升级危险机制。
- 完成钉钉失败重试、接收人启停和投递失败可视化；补充端到端自动化测试。
- 验收标准：四种模拟场景可重复触发预期告警；同级不重复、升级会再通知；重启后固定域名无需修改。

### P1：小区试点版（建议 2–4 周）

- 接入少量真实设备，记录 MQ-2 预热、基线、原始 ADC/电阻比和标定参数，不只保存近似 ppm。
- 建立“小区—楼栋—单元—房间—设备”层级，以及值班班组、责任人和告警升级策略。
- 钉钉消息增加结构化告警卡片、现场确认入口和超时升级；必要时接入短信作为兜底通道。
- 完成 MQTT 下行：蜂鸣器/声光报警控制、设备回执、超时重试和指令审计。
- 验收标准：真实设备连续运行并具备离线监控；每条告警可定位到房间、责任人和完整处置记录。

### P2：生产化部署（建议 1–2 个月）

- 将 Spring Boot 与 MySQL 迁移到长期运行的云服务器或托管平台，设置 TLS、WAF、最小权限数据库账号和机密管理。
- 引入进程/容器健康管理、监控指标、日志集中采集、每日备份和定期恢复演练。
- 使用 Flyway/Liquibase 管理数据库版本；使用 Redis 或网关实现多实例共享限流和会话安全状态。
- 使用 SSE/WebSocket 替代主要页面的 3 秒轮询，并实现告警投递队列、重试、幂等和死信处理。
- 验收标准：完成故障、断网、重启和备份恢复演练；关键接口、告警延迟与通知成功率可监控。

### P3：产品化扩展（按业务优先级）

- 用真实摄像头目录、鉴权、抽帧、对象存储和回放替换当前模拟图片源；保留可解释证据、模型/阈值版本和人工确认边界。
- 增加地图/楼层图、设备巡检、传感器寿命、校准记录、风险评分和趋势报表。
- 建立规则模板、版本审批、灰度发布和不同场所策略，支持多租户与数据隔离。
- 对接物业工单、消防值班流程或其他企业协作平台，形成跨系统事件闭环。

## 7. 推荐的下一步

视觉模拟识别—钉钉上报—人工研判闭环已落地。下一步优先完成 P0 的“传感器场景模拟器 + 告警恢复/迟滞 + 服务一键守护”，并为钉钉失败重试和视觉事件端到端测试补强。真实设备、真实摄像头和云端生产化应在演示闭环稳定后进入 P1/P2/P3。
