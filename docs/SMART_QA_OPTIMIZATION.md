# 智能问答功能优化记录

更新日期：2026-08-31。

本文记录智能问答的当前架构、已完成优化、已知限制和后续路线。它用于约束产品表述、实现范围和验收标准，不替代消防部门的正式处置要求。

## 当前架构

请求链路：

```text
Vue 右下角全局悬浮挂件 / 白色小窗口问答界面
  -> Spring Boot /api/chat
  -> Flask rag-service
  -> 领域判断与知识检索
  -> 本机 Ollama /api/chat
  -> gpt-oss:120b-cloud
```

- 内置知识库负责提供告警处置、疏散、设备离线、阈值、误报和广播依据。
- `gpt-oss:120b-cloud` 由本机 Ollama 路由到云端推理，不是纯本地 GPU 模型。
- Ollama 或模型不可用、模型输出结构校验失败时，服务回退到本地知识库。
- RAG 服务完全不可用时，Spring Boot 再回退到后端内置安全规则。

## 已完成优化

| 项目 | 当前实现 | 验收结果 |
| --- | --- | --- |
| 模型接入 | 代码通过 Ollama `/api/chat` 调用 `gpt-oss:120b-cloud` | 单元测试覆盖请求格式与 `source=OLLAMA` 响应；当前运行环境为后端回退，未实测在线模型 |
| 结构化回答 | 返回风险等级、摘要、立即措施、核验步骤、升级条件、安全提示和知识来源 | 前端按安全处置卡片展示 |
| 兼容输出 | 保留原有 `answer` 和 `source` 字段 | 旧客户端仍可显示纯文本答案 |
| 输出校验 | 严格解析并校验模型 JSON；非法结构自动回退 | 已覆盖非法模型输出测试 |
| 风险下限 | 按匹配知识条目和可识别告警类型计算风险基线；模型只能提高、不能降低 | 单元测试覆盖直接离线问题和火情流程；跨服务类型标签问题仍见 P0 |
| 检索权重 | 离线、疏散、阈值、误报、广播等专用词高于“怎么办”等通用词 | “设备离线怎么办”命中离线处理知识 |
| 领域边界 | 无关问题直接拒答，不消耗模型请求 | 诗歌等问题返回本地域控结果 |
| 问候处理 | 问候语不继承前端当前选中告警 | 选中离线告警后发送“你好”仍为未评估风险 |
| 上下文追问 | 前端会携带当前活动告警 ID，Spring Boot 会把告警上下文传给 RAG | 已具备传递链路，但告警类型中文标签与 Flask 英文枚举尚不一致，模糊离线追问可能误判，见 P0 |
| 故障回退 | Ollama、RAG、输出解析分别有降级路径 | 模型不可用时接口仍返回 200；后端阈值回退文案目前有已知口径缺陷，见 P0 |
| 运行状态识别 | Spring Boot 探测 RAG `/api/health` 并返回知识服务状态、提供方和模型配置标签 | 可识别 RAG 服务是否可达，但该健康检查不执行 Ollama 推理；单次回答是否用模型以 `source=OLLAMA` 为准 |
| 窗口与可读性 | 登录后由右下角按钮打开非模态白色小窗口；桌面端最大约 `440 × 620 px`，移动端按视口自适应 | 不再占用整个页面，浅色背景下文字和处置卡片可读 |
| 提交状态 | 请求期间显示“正在分析”并禁用发送、快捷问题和语音入口 | 当前单窗口交互不会重复提交同一问题 |

上述表格描述的是代码能力和测试基线。2026-08-31 联调时 `/api/system/capabilities` 返回知识库 `FALLBACK_ONLY`，表示当前 Spring Boot 未连通 RAG 服务，回答使用后端规则回退。该回退目前会把固定为 `100 ppm` 的烟雾阈值误述为可设置任意正整数；设备 API 与告警规则仍强制 `100 ppm`，修复前不得把问答中的阈值文案作为配置依据。

## 待优化路线

### P0：安全正确性

#### 1. 告警状态与类型契约

当前 Spring Boot 会发送告警 `status`、严重级别、规则、浓度和阈值，但没有发送 `falseAlarm`；Flask 目前只实际使用设备号、告警类型、浓度和阈值，没有消费状态、严重级别和规则。同时 `alertType` 使用中文 `typeLabel`，Flask 的上下文分支却只识别英文 `smoke` / `offline`。直接包含“离线”等关键词的问题仍可命中知识条目，但“这个怎么办”等模糊追问可能把离线告警当成烟雾上下文。后续应统一稳定枚举并明确区分活动、已确认、已解决和误报告警。

验收标准：

- 已解决告警必须明确标注为历史记录。
- 已标记误报的告警不得生成正在发生火情的确定性表述。
- “当前怎么办”只对活动或已确认告警提供实时处置建议。
- Java 与 Flask 使用同一告警类型枚举，并覆盖离线告警模糊追问测试。

#### 2. 确定性风险策略

建立独立于模型的风险计算器，综合告警类型、状态、浓度、阈值和持续时间计算最低风险等级。阈值口径必须来自同一权威规则，不应散落在提示词或后端回退文案中；当前后端 `ChatService` 的“任意正整数”回答必须改为系统强制的 `100 ppm`。

验收标准：

- 模型不得把规则计算结果降级。
- 高浓度、持续超阈值等条件可按配置提升到紧急等级。
- 风险计算具有边界值和异常数据测试。
- Ollama、RAG 本地回退和 Spring Boot 回退对阈值给出一致口径。

### P1：稳定性与数据边界

#### 3. 云端数据最小化

当前模型上下文包含设备编号、告警类型、浓度、阈值和状态。应提供设备编号脱敏、字段白名单和是否允许发送告警上下文的配置，并在产品界面明确云端推理边界。

验收标准：

- 默认只发送回答所需的最少字段。
- 日志中不记录完整提示词、JWT、设备令牌或敏感设备标识。
- 禁用云端上下文后仍能使用本地知识库回答。

#### 4. 可观测性、限流与熔断

记录模型耗时、成功、超时、结构校验失败和各级回退次数；为 `/api/chat` 增加按用户或客户端限流，并在连续失败后短暂熔断。

验收标准：

- 能区分模型失败、RAG 失败和本地规则回退。
- 熔断期间不重复等待已知不可用的模型。
- 监控不记录问题正文和模型完整回答。

#### 5. 生产 WSGI 服务

当前 RAG Docker 镜像使用 Flask 开发服务器。生产容器应改用 Gunicorn 等 WSGI 服务，并配置并发、请求超时、优雅退出和健康检查。

### P2：检索与交互体验

#### 6. 多条知识联合检索

由当前 Top-1 关键词匹配升级为 Top-K 检索，对告警处置、人员疏散等相关条目去重后共同提供给模型；再评估是否需要向量检索。

#### 7. 并发会话扩展

当前前端在一次请求完成前会禁用再次提交，单窗口内不会产生乱序回答。若后续开放并行提问、多会话或后台继续生成，应为请求和消息增加稳定标识，并把回答关联到对应问题，避免不同请求完成顺序造成对话错位。

#### 8. 多轮对话

当前每个问题独立处理，只使用当前告警而不使用历史聊天。后续如加入多轮上下文，应限制历史条数、过滤无关内容，并防止旧告警上下文污染新问题。

## 测试基线

当前应持续覆盖：

- 相关问题成功调用 Ollama。
- 模型不可用时回退本地知识库。
- 模型返回非法结构时回退。
- 模型不能降低知识库风险等级。
- 无关问题不调用模型。
- 问候语不继承选中告警风险。
- 模糊追问可以使用活动告警上下文。
- Java 后端字段映射和 Vue 生产构建通过。

每次修改提示词、风险规则或知识库后，都应运行 RAG 单元测试、后端测试和前端生产构建，并至少执行一次真实 `/api/chat` 端到端请求。
