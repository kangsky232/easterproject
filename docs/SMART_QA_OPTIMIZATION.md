# 智能问答功能优化记录

更新日期：2026-08-24。

本文记录智能问答的当前架构、已完成优化、已知限制和后续路线。它用于约束产品表述、实现范围和验收标准，不替代消防部门的正式处置要求。

## 当前架构

请求链路：

```text
Vue 问答界面
  -> Spring Boot /api/chat
  -> Flask rag-service
  -> 领域判断与知识检索
  -> 本机 Ollama /api/chat
  -> gpt-oss:120b-cloud
```

- 内置知识库负责提供告警处置、疏散、设备离线、阈值、误报和广播依据。
- `gpt-oss:120b-cloud` 由本机 Ollama 路由到云端推理，不是纯本地 GPU 模型。
- Ollama 或模型不可用、模型输出结构校验失败时，服务回退到本地知识库。
- RAG 服务完全不可用时，Spring Boot 再回退到后端内置安全规则。

## 已完成优化

| 项目 | 当前实现 | 验收结果 |
| --- | --- | --- |
| 模型接入 | 通过 Ollama `/api/chat` 调用 `gpt-oss:120b-cloud` | 真实请求返回 `source=OLLAMA` |
| 结构化回答 | 返回风险等级、摘要、立即措施、核验步骤、升级条件、安全提示和知识来源 | 前端按安全处置卡片展示 |
| 兼容输出 | 保留原有 `answer` 和 `source` 字段 | 旧客户端仍可显示纯文本答案 |
| 输出校验 | 严格解析并校验模型 JSON；非法结构自动回退 | 已覆盖非法模型输出测试 |
| 风险下限 | 按知识条目与告警类型计算风险基线；模型只能提高、不能降低 | 离线问题最低为中风险，火情流程最低为高风险 |
| 检索权重 | 离线、疏散、阈值、误报、广播等专用词高于“怎么办”等通用词 | “设备离线怎么办”命中离线处理知识 |
| 领域边界 | 无关问题直接拒答，不消耗模型请求 | 诗歌等问题返回本地域控结果 |
| 问候处理 | 问候语不继承前端当前选中告警 | 选中离线告警后发送“你好”仍为未评估风险 |
| 上下文追问 | “这个怎么办”等明确追问可以使用当前告警 | 保留告警上下文问答能力 |
| 故障回退 | Ollama、RAG、输出解析分别有降级路径 | 模型不可用时接口仍返回 200 和安全知识答案 |
| 运行状态识别 | Spring Boot 实时探测 RAG 健康状态并返回知识库状态、模型提供方和模型名 | 不再把已运行的知识库硬编码为未连接 |

## 当前配置

| 变量 | 默认值 | 说明 |
| --- | --- | --- |
| `OLLAMA_BASE_URL` | 本机运行时 `http://127.0.0.1:11434` | Docker 中默认访问宿主机 Ollama |
| `OLLAMA_MODEL` | `gpt-oss:120b-cloud` | 当前模型标签 |
| `OLLAMA_TIMEOUT_SECONDS` | `120` | 模型调用超时 |
| `OLLAMA_MAX_TOKENS` | `768` | 结构化回答最大生成量 |
| `OLLAMA_KEEP_ALIVE` | `10m` | Ollama 模型保活设置 |
| `RAG_TIMEOUT_SECONDS` | `130` | Spring Boot 等待 RAG 的超时，应大于模型超时 |
| `RAG_HEALTH_URL` | 本机运行时 `http://127.0.0.1:5001/api/health` | Spring Boot 探测 RAG 能力的地址 |
| `RAG_HEALTH_TIMEOUT_SECONDS` | `2` | RAG 健康探测超时 |

## 待优化路线

### P0：安全正确性

#### 1. 告警状态感知

当前 Spring Boot 已传递告警 `status` 和 `falseAlarm` 相关信息，但 RAG 主要依据告警类型、浓度和阈值生成上下文。后续应明确区分活动、已确认、已解决和误报告警，避免把历史告警描述为当前风险。

验收标准：

- 已解决告警必须明确标注为历史记录。
- 已标记误报的告警不得生成正在发生火情的确定性表述。
- “当前怎么办”只对活动或已确认告警提供实时处置建议。

#### 2. 确定性风险策略

建立独立于模型的风险计算器，综合告警类型、状态、浓度、阈值和持续时间计算最低风险等级。阈值比例必须由业务配置，不应散落在提示词中。

验收标准：

- 模型不得把规则计算结果降级。
- 高浓度、持续超阈值等条件可按配置提升到紧急等级。
- 风险计算具有边界值和异常数据测试。

### P1：稳定性与数据边界

#### 3. 云端数据最小化

当前模型上下文包含设备编号、告警类型、浓度、阈值和状态。应提供设备编号脱敏、字段白名单和是否允许发送告警上下文的配置，并在产品界面明确云端推理边界。

验收标准：

- 默认只发送回答所需的最少字段。
- 日志中不记录完整提示词、JWT、设备令牌或敏感设备标识。
- 禁用云端上下文后仍能使用本地知识库回答。

#### 4. 可观测性、限流与熔断

记录模型耗时、成功、超时、结构校验失败和各级回退次数；为 `/api/chat` 增加按用户或客户端限流，并在连续失败后短暂熔断。

验收标准：

- 能区分模型失败、RAG 失败和本地规则回退。
- 熔断期间不重复等待已知不可用的模型。
- 监控不记录问题正文和模型完整回答。

#### 5. 生产 WSGI 服务

当前 RAG Docker 镜像使用 Flask 开发服务器。生产容器应改用 Gunicorn 等 WSGI 服务，并配置并发、请求超时、优雅退出和健康检查。

### P2：检索与交互体验

#### 6. 多条知识联合检索

由当前 Top-1 关键词匹配升级为 Top-K 检索，对告警处置、人员疏散等相关条目去重后共同提供给模型；再评估是否需要向量检索。

#### 7. 前端等待与并发控制

模型请求期间显示“正在分析”，禁止同一输入重复提交，并用请求标识保证回答插入到对应问题之后，避免并发请求完成顺序不同导致对话错位。

#### 8. 多轮对话

当前每个问题独立处理，只使用当前告警而不使用历史聊天。后续如加入多轮上下文，应限制历史条数、过滤无关内容，并防止旧告警上下文污染新问题。

## 测试基线

当前应持续覆盖：

- 相关问题成功调用 Ollama。
- 模型不可用时回退本地知识库。
- 模型返回非法结构时回退。
- 模型不能降低知识库风险等级。
- 无关问题不调用模型。
- 问候语不继承选中告警风险。
- 模糊追问可以使用活动告警上下文。
- Java 后端字段映射和 Vue 生产构建通过。

每次修改提示词、风险规则或知识库后，都应运行 RAG 单元测试、后端测试和前端生产构建，并至少执行一次真实 `/api/chat` 端到端请求。
